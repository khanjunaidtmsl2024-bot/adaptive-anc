# SIH 2026 — SIH26052 AI/ML Adaptive Defence ANC System

## Complete Project Handoff / Research Context

### 1. PROJECT IDENTITY

**Problem Statement:** SIH26052
**Organization:** DRDO
**Category:** Hardware
**Theme:** Smart Vehicles / Defence-oriented embedded system
**Project:** AI/ML-enabled Adaptive Active Noise Cancellation (ANC) system.

The official problem statement asks for a system capable of suppressing:

* stationary noise
* non-stationary noise
* impulsive noise

while preserving speech intelligibility and operating in real time on embedded hardware.

The specified evaluation targets are approximately:

* **SNR > 15 dB**
* **STOI > 0.85**
* **PESQ > 2.5**
* real-time embedded operation

The problem statement specifically mentions defence noises such as:

* gunshots
* artillery
* helicopter/rotor noise
* armored vehicle/engine noise
* drones
* wind
* sirens

and suggests AI/ML speech enhancement combined with adaptive filtering, STFT/time-domain processing, complex-domain processing, perceptual losses, and embedded deployment. ([Smart India Hackathon][1])

---

# 2. CORE OBJECTIVE

The project is **not simply "build a noise-cancelling headphone."**

The intended system is a **hybrid AI + DSP + adaptive-filtering communication/noise-control system**.

The basic philosophy is:

> **Use AI/ML to understand and suppress complex speech-corrupting noise, while using classical adaptive signal processing to handle acoustic-path adaptation and residual noise.**

The system must therefore combine:

```text
             REAL WORLD
                 │
        Defence acoustic noise
                 │
       ┌─────────┴─────────┐
       │                   │
 Reference Mic          Primary Mic
       │                   │
       │              Speech + Noise
       │                   │
       ▼                   ▼
 Reference Path       AI Speech Enhancement
       │                   │
       │                   ▼
       │             Enhanced Speech
       │                   │
       └──────► Adaptive/Residual Filtering
                           │
                           ▼
                    Communication Audio
                           │
                           ▼
                     Headset/Speaker
```

For a true **feedforward acoustic ANC loop**, there is additionally an error microphone:

```text
Reference microphone
        │
        ▼
   Controller
        │
        ▼
 Anti-noise speaker
        │
        ▼
 Acoustic environment
        │
        ▼
 Error microphone
        │
        └──────── feedback/update
```

The important distinction is that **speech enhancement and physical acoustic ANC are related but not identical problems**.

# 3. THE MOST IMPORTANT ARCHITECTURAL IDEA

The project should be thought of as **multiple processing layers**, not one magical neural network.

### Layer 1 — Audio acquisition

Microphones capture the acoustic environment.

Potential prototype hardware discussed:

* Raspberry Pi 4
* USB/I²S audio interface
* WM8960 codec/audio board
* separate microphone locations/modules
* primary microphone
* reference microphone
* potentially an error microphone depending on the final ANC topology
* headphone/speaker output

The two microphones have **different purposes**.

### Reference microphone

Placed where it can capture the incoming noise **before or differently from the speech/error location**.

Purpose:

* predict noise
* provide reference signal to adaptive ANC
* improve causality
* allow the controller to anticipate incoming noise

### Primary microphone

Captures the signal relevant to communication:

```text
speech + noise
```

It is the main signal that the AI speech-enhancement system attempts to clean.

### Error microphone

If implementing physical feedforward ANC:

```text
error microphone
       ↓
residual noise
       ↓
adaptive filter update
```

It tells the controller:

> "How much noise is still present after anti-noise has been produced?"

This distinction is fundamental.

---

# 4. WHY MICROPHONE PLACEMENT MATTERS

The reference and primary/error microphones cannot simply be treated as identical sensors at the exact same location.

If they are colocated, their signals become highly correlated and the reference signal may contain excessive desired speech.

That can create:

* speech leakage into the reference
* poor noise prediction
* adaptive-filter misadjustment
* speech cancellation
* reduced ANC stability
* poor causality

The reference microphone therefore needs to capture a useful **predictive representation of the noise**, while minimizing desired-speech contamination.

The project has specifically been investigating how to physically separate microphone roles even when using a two-channel audio device.

# 9. STFT

STFT = **Short-Time Fourier Transform**.

It converts a time-domain signal into a time-frequency representation.

Instead of looking only at:

```text
amplitude vs time
```

we obtain:

```text
frequency vs time
```

This is useful because speech and noise occupy different spectral-temporal patterns.

Example:

```text
Time
 ─────────────────────►

Frequency
│
│     speech harmonics
│      ╱╲
│     ╱  ╲
│ ───────────── rotor noise
│
│          impulse
│             │
│             │
▼
```

Important STFT parameters:

* sampling rate
* FFT size
* window length
* hop size
* overlap
* window function
* number of frequency bins

---

# 10. OVERLAP-ADD

STFT cannot simply process isolated blocks independently.

Frames overlap:

```text
Frame 1: ████████
Frame 2:     ████████
Frame 3:         ████████
```

After inverse FFT, they must be reconstructed using **overlap-add (OLA)**.

Incorrect overlap/add implementation can produce:

* clicks
* discontinuities
* amplitude modulation
* reconstruction artifacts
* latency problems

Therefore STFT → AI → iSTFT → OLA is a core engineering component.

---

# 11. ALIASING / ANTI-ALIASING

This is one of the fundamentals that must be understood before claiming the audio pipeline is complete.

### Aliasing

If sampling frequency is too low, frequencies above Nyquist can fold into lower frequencies.

Nyquist frequency:

```text
f_N = Fs / 2
```

Example:

If:

```text
Fs = 16 kHz
```

then:

```text
Nyquist = 8 kHz
```

Signals above 8 kHz cannot be correctly represented.

Therefore the ADC normally requires an **anti-aliasing low-pass filter before sampling**.

This is hardware + signal-processing knowledge, not merely an AI issue.

# 12. NOISE CLASSIFICATION

The system must distinguish conceptually between three major categories.

## A. Stationary noise

Characteristics:

* statistics change slowly
* relatively predictable
* approximately constant over time

Examples:

* steady engine
* ventilation
* constant machinery
* electrical hum

Classical adaptive filtering can perform well here.

---

## B. Non-stationary noise

Characteristics:

* changes over time
* frequency/amplitude changes
* difficult to model with fixed filters

Examples:

* changing engine RPM
* helicopter rotor variation
* moving vehicle
* changing wind
* varying machinery

This is where adaptive algorithms and AI become more useful.

---

## C. Impulsive noise

Characteristics:

* extremely short duration
* very high amplitude
* broadband/transient
* can destabilize traditional adaptive filters

Examples:

* gunshots
* explosive impulses
* metal impacts
* sudden mechanical events

This is one of the **hardest parts of SIH26052**.

A recent uploaded research paper specifically demonstrates that conventional FxLMS/FxNLMS can perform poorly under impulsive disturbances and investigates a detection + Kalman hybrid approach. 

That paper reports approximately:

* FxLMS: ~0.06–0.12 dB cancellation
* FxNLMS: ~1.18–1.28 dB
* Kalman approach: ~4.27–5.15 dB

for its particular experimental/simulation setup. These numbers **must not be treated as our expected project performance**; they are evidence that impulsive noise needs special treatment. 

---

# 13. CLASSICAL ADAPTIVE FILTERS

## LMS

Least Mean Squares.

Basic idea:

```text
prediction
   ↓
calculate error
   ↓
adjust coefficients
   ↓
repeat
```

Advantages:

* simple
* cheap computationally
* easy to implement

Disadvantages:

* convergence can be slow
* sensitive to signal power
* weaker for rapidly changing/impulsive environments

---

# 14. NLMS

Normalized LMS.

It modifies LMS so the update is normalized according to input signal power.

Conceptually:

```text
LMS:
large input → potentially huge update

NLMS:
large input → normalized update
```

Advantages:

* more stable under varying input amplitude
* generally faster/more robust than ordinary LMS
* inexpensive

NLMS is an important candidate for residual adaptive filtering.

---

# 15. FxLMS

Filtered-x LMS.

This is extremely important for **physical ANC**.

Why?

Because the anti-noise generated by the controller does not instantly reach the listener/error microphone.

There is a physical **secondary acoustic path**:

```text
controller
   ↓
speaker
   ↓
DAC
   ↓
speaker acoustics
   ↓
air
   ↓
error microphone
```

Therefore the reference signal must be filtered using an estimate of that secondary path.

The standard feedforward ANC relationship can be represented as:

```text
reference x(n)
      ↓
 adaptive filter W(z)
      ↓
 anti-noise
      ↓
 secondary path S(z)
      ↓
     error
```

The uploaded Kalman/ANC paper explicitly defines the reference signal, primary path, secondary path, adaptive filter, anti-noise and error relationship. 

---

# 16. FxNLMS

FxNLMS = Filtered-x Normalized LMS.

It combines:

* filtered-x compensation
* NLMS normalization

It is generally more robust than basic FxLMS when input power varies.

But it still has difficulty with highly impulsive disturbances.

---

# 17. KALMAN FILTER

Kalman filtering is another adaptive/state-estimation approach.

Conceptually:

```text
previous state
      ↓
predict next state
      ↓
new microphone measurement
      ↓
calculate innovation
      ↓
update state
```

It is attractive for dynamic environments because it explicitly models evolving system states.

The uploaded 2026 paper maps ANC filter coefficients into the Kalman state and uses the error microphone as the measurement. 

It also proposes:

```text
impulse detected
      ↓
Kalman ANC

normal noise
      ↓
NLMS/FxLMS ANC
```

as a hybrid strategy. 

This is particularly relevant to SIH26052.

# 19. AI/ML COMPONENT

The neural network is intended primarily to learn patterns that conventional filters struggle with.

Deep Complex Convolution Recurrent Network.

Important because:

# 20. COMPLEX-DOMAIN PROCESSING

Complex STFT coefficients contain:

```text
real part
+
imaginary part
```

which encode:

* magnitude
* phase

A system that modifies magnitude while completely ignoring phase can introduce reconstruction errors/artifacts.

Therefore the project has investigated **complex-domain AI processing**, particularly architectures such as DCCRN.

The problem statement itself explicitly mentions complex-domain processing. ([Smart India Hackathon][1])

# 28. CAUSALITY

Causality is one of the most important concepts in this project.

A real-time system cannot depend heavily on future samples.

Bad:

```text
future audio
   ↓
AI
   ↓
current output
```

because future audio does not yet exist.

Good:

```text
past + current audio
        ↓
      model
        ↓
     output
```

A model may technically be fast but still unsuitable if it uses a huge future context.

# 31. DMA

DMA = Direct Memory Access.

Instead of the CPU manually copying every audio sample:

```text

```

```text

```

while the CPU performs other work.

DMA is important for stable real-time audio.

# 33. IMPORTANT AUDIO FAILURES

The prototype must watch for:

### Clipping

Signal exceeds ADC range.

### Buffer underrun

Processor cannot supply audio quickly enough.

### Buffer overrun

Input arrives faster than it is processed.

### Channel mismatch

Left/right channels are swapped or incorrectly mapped.

### Clock drift

Different devices run at slightly different rates.

### DC offset

Signal has unwanted constant offset.

### Excessive gain

Can destroy model performance and cause clipping.

# 34. SECONDARY PATH

This is one of the **most important ANC concepts**.

The controller generates:

```text
anti-noise
```

but that signal passes through:

```text
DAC
→ amplifier
→ speaker
→ air
→ microphone
```

This physical path is called the:

**secondary path S(z)**.

It must be estimated because the adaptive algorithm needs to understand how its output reaches the error microphone.

The uploaded ANC paper explicitly models this secondary path and filtered reference signal. 

---

# 35. PRIMARY PATH

The primary acoustic path describes how the unwanted noise reaches the error location.

```text
noise source
   ↓
environment
   ↓
error microphone
```

represented approximately as:

```text
P(z)
```

The ANC system effectively deals with:

```text
Primary path P(z)
+
Secondary path S(z)
```

If the adaptive controller's predicted anti-noise arrives too late:

```text

```

For successful feedforward ANC:

```text

      ↓

      ↓

      ↓
```

# 42. IMPORTANT WARNING ABOUT GUNSHOTS

A gunshot is not merely "very loud stationary noise."

It can be:

```text
very high amplitude
+
very short duration
+
broadband
+
rapidly changing
```

Therefore the adaptive filter can receive a huge error and make an inappropriate coefficient update.

This can cause:

* instability
* coefficient explosion
* slow recovery
* divergence
* speech corruption

This is exactly why robust impulse handling is important.

# 53. EQUATIONS YOU SHOULD EVENTUALLY UNDERSTAND

Basic signal:

```text
y[n] = speech[n] + noise[n]
```

ANC error:

```text
e[n] = d[n] - y_anti[n]
```

More realistically, the anti-noise passes through the secondary path:

```text
e[n] = d[n] - S(z)y[n]
```

Adaptive filter:

```text
y[n] = wᵀ[n]x[n]
```

LMS:

```text
w[n+1] = w[n] + μ e[n] x[n]
```

FxLMS conceptually:

```text
w[n+1] = w[n] + μ e[n] x'[n]
```

where:

```text
x'[n] = Ŝ(z) * x[n]
```

The exact sign convention can vary by formulation.
